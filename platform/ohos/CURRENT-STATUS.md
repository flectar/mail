## 开发包与设备范围

当前包是第四轮 CPU 性能修复的 **ARM64 debug 开发包**，不是完成全部验收的发布版。
包元数据为 `moe.kiwi.FlectarMail`、`0.1.0`，声明支持 `phone`、`tablet`、`2in1`。
最低兼容 HarmonyOS 6.0.0／API 20，编译使用 Rust 1.97、DevEco Studio
26.0.0.851 和 API 26.0.0.105 SDK。最低版本及三类设备仍需各自实测。

已测试设备仅一台 MatePad Pro（WEB-W00，HarmonyOS 7／API 26）。主要测试窗口为
2880×1786，另验证过 1008×1714 悬浮窗恢复全屏；没有将窗口尺寸变化当作
Surface 销毁重建验证。本轮没有安装或使用 Simulator。

最新本地签名产物 `animation-font-prewarmed-signed.hap`，161835464 字节，
SHA-256 为 `2e24b143746e92cf8ce158985e78e18ded7939fdea0144400dceec3570a7e3aa`。
这是本次已安装包的身份记录；重新构建或使用自己的签名后不要求文件摘要相同。
构建、签名和安装步骤见 [构建指南](README.md)。

## 最新性能结论

第四包后台构造独立的邮件字体模板；界面只读取已就绪模板，不等待后台任务。
三次进程冷启动首用均命中模板，首次邮件事件汇总窗口由第三包的216–226ms降至53–55ms，
抬起到首候选呈现由154–163ms降至56–94ms。候选首帧可能只是输入反馈，不代表正文完成。
其中两次冷启动仍各有一个约58ms候选间隔。

第四包六场单轮暖态回归中，设置、侧栏及回复的抬起后最大候选间隔为17–42ms，
短HTML仍有一次58ms间隔。本轮真实滚动条操作确认正文偏移，按下／抬起闭区间的
最大间隔16.737ms；没有据此宣称持续滚动、惯性、稳定60 FPS或整个界面完全无卡顿。
该轮没有继续扩大性能优化范围。完整表格、静态像素范围和包身份见
[动画性能记录](ANIMATION-PERFORMANCE.md)。

历史 schema 1 把 RS 第一列误称实际呈现 FPS；原数字及JSON保留，但以其确认
实际呈现提升或流畅通过的结论已经撤回。schema 2 保存 `flushTime:presentTime`
双列并用第二列计算呈现间隔，语义依据公开 Rosen 源码，尚未逐字匹配设备版本。
阶段计时、复制耗时与像素／功能结果独立保留，详见
[性能采集指南](PERFORMANCE.md)及[测量口径](MEASUREMENT-SCHEMA.md)。
